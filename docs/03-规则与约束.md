# RollPlay 规则与约束

> 三类规则：一、边界与鲁棒性（S 系列）二、并发安全（C 系列）三、可视化渲染（R 系列）。每条都写明"规则 / 现状 / 依据"，避免凭感觉改动。

---

## 一、边界安全与鲁棒性

### S-1 状态机互斥
任一时刻只允许一个扫描任务；`scanning` 时禁止添加/移除目录、再次扫描、清空残留。
`playing` 与 `scanning` 可并存（增量收录、后台刷新不打断播放），但"切换媒体池"必须确认。
**现状：已实现（扫描锁 + 播放中禁重建轮次；清空残留已纳入）。**

### S-2 危险操作二次确认
必须经 `confirmDialog`：移除目录、刷新媒体库切池、提前换批、清空残留/重置。
停止播放只需轻提示（可重来）。
**现状：已实现。**

### S-3 播放失败熔断（防疯狂跳过）
1. 单文件失败 → 跳过 + 计数。
2. 连续失败达阈值（`FUSE=10`）→ 暂停推进，提示"连续 N 首无法播放"，停止无限跳。
3. 修双触发竞态：失败路径推进前用代次 token 抑制该文件滞留的 `error` 事件。
4. 恢复播放前做路径存在性校验，失效路径预过滤并提示。
**现状：已实现（`playback.js` 代次 token + `pendingFail` 定时接管 + `_advance` 宏任务统一推进 + `onFuseBreak`）。**

### S-4 缓存一致性
1. `restoreSession` 以「存档 + 当前内存」合并，不无条件用旧 `dirs` 覆盖当前变更。
2. 目录变更后 pool 与 dirs 不一致 → 标「待刷新」并提示。
3. `removeDir` 后从 pool 剔除该目录文件或强制提示刷新。
4. 提供「清空残留」入口（`clearSession()` + 重置 state）作兜底。
5. 修复 `pool 空即 return` 的短路，保证 dirs 与恢复按钮正常。
**现状：已实现。**

### S-5 扫描资源熔断
1. 扫描前预估文件数/目录数，超阈值 → 确认 + 建议拆分目录。
2. 根目录/盘符 → 强警告，默认需确认才扫。
3. 后端 `MAX_SCAN_FILES=100000` + 扫描超时（180s），超限截断并标 `truncated`，不无限占内存。
4. 扫描中显示「已扫进度」。
**现状：1、2、3 已实现；4 为进度轮询显示。**

### S-6 输入与路径校验
路径 trim、空值拦截、重复目录拦截、后端 `stat` + 类型校验（`NOT_DIRECTORY`）、非法路径 `assertSafePath`。
**现状：齐全。**

### S-7 持久化鲁棒性
节流合并写入、坏存档降级、payload 版本化（`SESSION_VERSION=1` + 迁移器）、清空即删键。
**现状：已实现。**

### 规则 → 操作映射

| 用户操作 | 拦截/确认 | 依据 |
|---|---|---|
| 空路径 / 重复目录 | toast 拦截 | S-6 |
| 扫描中添加 / 移除目录 | 按钮禁用 + toast | S-1 |
| 添加盘符根目录 | 强警告确认 | S-5 |
| 移除目录 | 确认对话框 | S-2 |
| 刷新媒体库 | 切池确认 | S-2 |
| 提前换批 | 确认对话框 | S-2 |
| 清空残留 | 确认对话框 | S-2 / S-4 |
| 播放中重建轮次 | 按钮禁用 | S-1 |
| 恢复播放遇失效路径 | 预过滤 + 提示 | S-3 / S-4 |
| 连续播放失败 | 熔断暂停 + 提示 | S-3 |

## 二、并发安全

| 编号 | 并发点 | 风险 | 规则 |
|---|---|---|---|
| C-A | 扫描轮询 | 全局单定时器被覆盖 → 旧轮询不停、requestId 错乱、结果混合 | `pollTimers` 按 requestId 绑定 + `stopPoll(id)`；同一时刻至多一个活动扫描 |
| C-B | 刮削请求 | 快速切歌后旧封面/歌词晚到 → 张冠李戴 | 递增 token/路径校验，响应时与当前曲匹配才采用 |
| C-C | 播放推进 | `ended` 与手动 next 撞车 → 多跳 | 统一串行推进入口 + 批次代次 token，同代次禁止重复推进 |
| C-D | 切池/停止 | 旧 audio 残留 `error`/`ended` 干扰新轮 | 先暂停、`playback.reset()` 清 src 并抑制残留事件，再切池 |
| C-E | 持久化 | persist 节流窗口内 restore 读到旧数据 | 以最新落盘为准，写入原子，低风险可接受 |

**互相制约**：C-C 与 S-3 合并为同一引擎改造（根治疯狂跳过的双重来源）；C-A 与 S-1 双层防护扫描并发；C-B 与 S-4 互补避免错位；C-D 保证状态切换后引擎干净。

## 三、可视化渲染规则（环形频谱防"阶梯感"）

数据层 → 绘制层 → 验收层，缺一层就会退回"凭感觉画环"。

**数据层**
- `N ≤ 64` 取左声道前 N 个；`N > 64` **必须插值**，禁止 `arr[i % 64]` 式最近邻复制。
- 默认三次插值（Catmull-Rom），仅性能不达标才降级线性；边界点用线性外推防越界。
- 顺序固定：**钳制 → 插值 → 平滑 → 绘制**，不可颠倒。
- 指数平滑：`attack 0.3~0.5`、`release 0.05~0.15`；连续 3 帧 > 0.98 视为异常峰值，压到 0.95。
- 性能自检：rAF 中统计最近 30 帧均值，> 14ms 则 N 降 25%（不低于 48），仍超则降级线性。

**绘制层**
- 圆角矩形条，`r = barWidth * 0.5`（性能不足可 0.3，但不得为 0）。
- 不开 `imageSmoothingEnabled = false`；条间距 ≥ `barWidth * 0.4`。
- 辉光 `shadowBlur ∈ [4,12]`、透明度 ≤ 0.6，只作用于频谱条，不作用于封面与文字。
- 沿角度做色相渐变，相邻条色相差 ≤ 8°，禁止硬切色块。
- 每根条最小高度 = 内径 8%–12%，保证静音时环形完整不断裂。

**验收层**：插值存在性、无最近邻、有钳制、平滑顺序正确、圆角、30 帧 ≤ 14ms、静音完整性；可选视觉回归——固定测试音频渲染 3 帧，相邻条高差最大值 ≤ 最大条高 30%。

**人工兜底**：辉光强度、色相范围、旋转速度只给区间由人调；性能档位交用户选；不逆向改他人壁纸未暴露的代码。

## 四、交付纪律（每次改动都要走）

1. `node --check` 所有改动的 `.js` / `.mjs`（含 `modules/*`、`providers/*`）。
2. 几何与动效：浏览器 `getComputedStyle` / 定时 `getBoundingClientRect` 采样，数值对齐才交付。
3. 升 `public/index.html` 的 `?v=` 字母（当前 `20261106q`），否则缓存会掩盖改动。
4. 涉及后端：重启服务并 `Invoke-WebRequest` 验 200。
5. 交付时如实标注"未实测项"（如会弹资源管理器打断用户的操作），不要写成已验证。

---

## 五、不可动摇的承诺

- **只读**：后端无任何删除/写入媒体文件的代码，前端无删除入口；「清空残留」只清 IndexedDB 会话。
- 不做账户系统。
- 界面参数以 `UI putout/` 标注为准，改动前先解析真值，不凭截图猜。
