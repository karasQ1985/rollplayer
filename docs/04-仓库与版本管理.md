# 仓库与版本管理规范

本文件是 RollPlay 的**仓库操作手册**：哪些文件进版本库、提交前要过哪几道检查、分支与发布怎么走、出问题怎么回滚。

## 一、入库边界

| 路径 | 是否入库 | 原因 |
|---|---|---|
| `server.mjs`、`meta-*.mjs`、`public/**`、`icon/**` | ✅ 入 | 代码与静态资源 |
| `docs/**`、`README.md`、`LICENSE` | ✅ 入 | 文档与许可 |
| `package.json`、`package-lock.json` | ✅ 入 | 依赖锁定，保证他人 `npm install` 结果一致 |
| `.gitignore`、`.gitattributes`、`.editorconfig` | ✅ 入 | 仓库行为由它们定义 |
| `tools/*.mjs`、`tools/*.py` | ✅ 入 | 可复用的自测/基准脚本 |
| `data/`（SQLite + 封面缓存 + `.lock`） | ❌ 不入 | 本机运行产物，含你的音乐库路径，且会随使用增长 |
| `UI putout/`（94MB 标注导出） | ❌ 不入 | 体积过大，属设计参考而非交付物 |
| `node_modules/`、`node/`（绿色版 Node） | ❌ 不入 | 依赖可由 `npm install` 重建 |
| `tools/scratch/`、`*.log`、`bench*.json`、`scan*.json` | ❌ 不入 | 一次性调试产物 |
| 任何 `.mp3/.flac/...` 音频 | ❌ 不入 | 版权与体积 |

> 判断口径：**换一台干净的电脑 clone 下来，能不能靠仓库里现有的东西跑起来并产出同样结果**。不能重建的一律不入，能重建的一律不入。

## 二、提交前检查清单

每次 `git commit` 之前跑完这四项（有 `npm run check` 可以一次过前两项）：

```bash
# 1. 语法
npm run check

# 2. 静态资源版本串（改了 public/ 下任何 js/css/html 就必须升）
#    public/index.html 里的 style.css?v= 与 app.js?v=

# 3. 确认没有把运行产物带进暂存区
git status --porcelain
git diff --cached --stat      # 应只出现代码/文档，不应出现 data/、*.log、*.sqlite

# 4. 确认没有超大文件（PowerShell）
git ls-files | ForEach-Object { $s=(Get-Item -LiteralPath $_ -ErrorAction SilentlyContinue).Length; if ($s -gt 1000000) { "{0:N0}`t{1}" -f $s, $_ } }
#    ↑ 空输出为佳
```

三项硬规则：

1. **改了前端就要升 `?v=`**，否则用户浏览器拿到旧缓存，行为与代码不一致。
2. **改了 `server.mjs` / `meta-*.mjs` 必须重启服务**再验证，热改不生效。
3. **`data/` 永远不进暂存区**；如果发现自己误 `git add -f` 了，用 `git rm --cached -r data` 撤回索引，不要用 `git reset --hard` 去掩盖。

## 三、提交信息格式

统一 `类型: 中文摘要`，类型取以下一种：

| 类型 | 用于 |
|---|---|
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `refactor` | 结构调整，行为不变 |
| `style` | 仅样式/视觉 |
| `docs` | 仅文档 |
| `chore` | 仓库配置、忽略规则、依赖 |
| `perf` | 性能优化 |

示例：

```
feat: 左抽屉点外部收起，弹窗内点击豁免
fix: 弹窗关闭后 260ms 内误判外部导致抽屉塌陷
style: 音量数字基准改为与歌曲信息栏对齐
chore: 忽略 tools/scratch 调试产物
```

正文写「改了什么 / 为什么 / 怎么验证」，一行一条，别把三类信息揉成一段。

## 四、分支与发布

- `main` 保持随时可运行，只接受「自查通过」的提交。
- 动结构（拆分模块、改 API 契约）时开 `feat/xxx` 分支，验完再合并回 `main`。
- 发版用轻量标签，和前端版本串一起走：

```bash
git tag -a v1.1.0 -m "抽屉交互与唱片动效完善"
git push origin v1.1.0
```

标签版本号与 `public/index.html` 的 `?v=` 串**不要求一致**：`?v=` 是缓存击穿用（每次改前端都变），tag 是功能里程碑。

## 五、回滚与恢复

```bash
# 看历史（含每次改动的文件清单）
git log --oneline --stat -20

# 撤销工作区某个文件的改动（未暂存）
git restore public/app.js

# 撤销已经暂存、但还没提交的改动
git restore --staged public/app.js

# 已经提交但想回退（保留历史，安全做法）
git revert <commit>

# 只想让文件回到某次提交的样子（会覆盖工作区，先确认没有未提交的成果）
git checkout <commit> -- public/style.css
```

禁止在共享分支上 `git push --force`；`main` 已推到 GitHub，改写历史会让协作者与克隆全部错位。

## 六、换机 / 备份

```bash
# 新机器
git clone https://github.com/karasQ1985/rollplayer.git
cd rollplayer
npm install
node server.mjs          # 或双击 start.bat

# 离线整仓备份（含全部历史，单文件）
git bundle create rollplay-backup.bundle --all
git clone rollplay-backup.bundle rollplay-restore

# 只想备份本地库（这不是代码，但丢了要重新刮削）
# 复制 data/meta/ 整个目录即可
```

## 七、网络与代理

若 `git push` 报 `Connection was reset` 而浏览器能打开 GitHub，说明系统走了本地代理但 git 没继承。按本机代理端口配置（只对本仓库生效，不污染全局）：

```bash
git config http.proxy  http://127.0.0.1:7890
git config https.proxy http://127.0.0.1:7890
git config --get http.proxy      # 复核
```

取消：

```bash
git config --unset http.proxy
git config --unset https.proxy
```

## 八、敏感信息底线

公开仓库，以下内容任何情况下不得提交：

- 真实媒体库路径与目录结构（如具体盘符下的私人整理目录）
- NAS / 主机名、局域网固定 IP、共享账号
- 任何 token、cookie、API key（本项目不存储第三方密钥）
- `data/meta/` 下的库文件与封面（内含文件路径与哈希）

提交前自检一条命令：

```bash
git grep -n -E "你的用户名|你的NAS名|真实盘符路径片段" $(git rev-list --all) 2>/dev/null
```

命中就说明历史里已经带上了，需要 `git filter-repo` 清理后重新推送（不要让公开仓库长期带着这些串）。
