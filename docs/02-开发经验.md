# RollPlay 开发经验

> 只记录**跨任务可复用**的结论与踩过的坑。按大类划分：A 标注还原 · B 交互与输入 · C 动效与时序 · D 浏览器实测 · E 后端与数据。

## A. 标注还原（marklion → 代码）

### A1. 解析 data.js
- 结构是 `marklion_artboard(<资源映射>,document.currentScript,<JSON>)`，**前缀不固定**（有的多一个 svg 映射对象）。正确做法：`raw.index('document.currentScript,')` 定位逗号后，再用 `JSONDecoder().raw_decode()` 从该偏移解析。
- 文字规格在 `textSegments[]`，不在 `style`；字号/字距/字重/颜色都在段里。
- 透明度有两个独立量：**节点级 `opacity`** 与 **fill 级 `fills[].opacity`**，不要用预览截图采样反推。
- `gradientStops[].color` 可能是十进制 ARGB 整数，需自己转 rgba。
- FRAME 外框常是空框（`kids=0`），真实尺寸要读子图形 `absoluteBoundingBox`。

### A2. 渐变方向
`data.js` 不给渐变手柄方向。可靠办法：**采样高分辨率 preview.png**（PIL 沿轴向取若干点），确认方向与停靠点，再用采样值反查落地的 CSS 渐变是否一致。
- 本项目海报真值：`linear-gradient(to top, rgba(0,132,255,.40) 0%, rgba(0,67,167,.40) 32.2%, rgba(0,9,67,.40) 100%)`；采样误差 0~5。

### A3. 几何迁移
- 先用标注的 `absoluteBoundingBox` 建立"标注坐标系 → 页面坐标系"的偏移，再逐元素换算；**不要凭视觉微调**。
- 变体对照（MusicPlayer）：无封面版宽 1210，有封面版宽 **1522**；`poster image` x 20→330、`Frame 75` x 340→650、`config main` 931.8→1241.8。结论：**封面露出 = 播放器加宽 +312、内容整体右移 +310、唱片本身不动**。
- 固定宽度面板改可拖拽调宽时，右侧元素右缘按 `right` 定位的基准是「基准宽 − 元素右缘」，写成「基准宽 − 元素左缘」会让整块左移自身宽度。

### A4. 字体
- 字号/字距/颜色都对但字形观感不符 → **先确认字族是否真的加载成功**。`document.fonts.check()` 有假阳性，用 canvas `measureText` 比宽度才可靠。
- 本项目字体：`public/assets/fonts/inter-var.woff2`；MIME 必须包含 `.woff2`。

### A5. 图标
- 组件图标真值在标注导出目录的**各组件 res 子目录**（官方 on/off 两套图标 + 透明度），不要凭截图或手绘推断。

## B. 交互与输入

### B1. 滚轮调音量（本项目反复返工的头号坑）
**结论：按住 Ctrl + 滚轮，按「方向」驱动，一个 wheel 事件一步，2%/格；不要按「位移」驱动；普通滚轮完全不接管。**

- 加了 Ctrl 前缀之后，滚轮调音量不再和"页面/列表要能正常滚"打架：没按 Ctrl 就一个字节都不动，抬手即回普通模式，没有残留状态。借的正是浏览器"Ctrl+滚轮=缩放"这个人人懂的临时模式语义，所以也不必去占 Shift（Shift 另有主：等比缩放拖拽）。
- 高精度/自由滚轮（罗技 MagSpeed）报的是**大量小 delta**：10–40 事件/秒，`deltaY` 常 < 5px。
- 所以"位移攒满 100px 才算一格""加位移门限 0.6 格""50ms 时间限速"这类设计在真机上表现为：
  - 小 delta 长时间攒不满 → **滚了不动 / 中途失去响应**；
  - 偶尔大 delta 经 `trunc` 一次算多格 → **一跳到底 / 失控**。
  两头同时出现，而且每加一层限制，手感越差——这就是"越改越回不去"的机制。
- 主流一致做法（Deezer Linux 补丁、VLC、KDE Plasma、jQuery 滑块教程）：`direction = -Math.sign(deltaY)`，`volume += step*dir`，**每事件都响应、忽略 deltaY 大小**，clamp 0~1，`preventDefault()`。Qt 官方对细分辨率设备给的两条路也是"累积到 120 再滚"或"每事件部分滚动"，**没有时间限速**。
- 本项目现行实现：事件只记一步进队列（`volPending`），`requestAnimationFrame` 每帧消费一步，余下排队下一帧；反向清队列、撞 0/100 清队列、队列上限 30 仅防极端爆发后滞后。这样**事件一个不丢**，只是排到下一帧。
- 若嫌自由滚轮到顶太快，正确调节是**降步进**（5%→3%/2%），不是加限速。现行为 2%。

**监听位置与冲突处理**
- 把 `wheel` 绑在 `#volumeBox` 上时，指针离开那块 66×271 的小区域就完全收不到事件，用户体感是"滚着滚着就失灵"——这是"中途失去响应"的一大成因，不是灵敏度问题。所以监听必须在 `window` 级。
- 现行让行顺序：① 没有 `ctrlKey` → 直接 `return`，一个字节都不动；② 叠了 `meta/shift/alt` → 让行，不与等比缩放快捷键抢；③ `deltaMode===2`、横向手势、正在拖滑块/进度条 → 让行；④ 其余 `preventDefault()` 拦掉浏览器缩放，按方向走一步。
- 合成 `WheelEvent` **不会触发浏览器默认滚动**，事件级只能验证"没抢/抢了音量"，真实滚动必须人手确认。
- 实测（页面内自检，单次执行、结果写 DOM 面板后截图）：起点 50% → Ctrl 上滚 3 次 **56%** → Ctrl 下滚 1 次 **54%** → 普通滚轮 3 次 **仍 54%（完全不接管）** → Ctrl+Shift / Ctrl+Alt **仍 54%** → Ctrl 上滚 10 次 **74%**。每格恰好 2%。
**与 `临时技术交流文档01/02/03` 的逐条裁定**（那三份是通用规范，前提是"播放器窗口内有明确音量热区"；本项目的需求不同，冲突项按用户需求为准）

| 三份文档的主张 | 本项目的落法 | 裁定 |
|---|---|---|
| 只绑音量容器，**明确反对 `window`/`document` 全局监听**（01 §一/§七、02 §一、03 §2.2 P03） | `window` 级监听 + **Ctrl 前缀**做触发条件 | **部分作废**。全局监听成立（用户要"任意位置"），但把"无条件接管"改成"Ctrl 才接管"，等价于把三份文档担心的"抢滚动"从根上消掉 |
| 位移累积：攒满一个单位才走一格、保留余数（01 §3.4、03 §3.4） | 每事件一步 + `rAF` 每帧消费一步 | **作废**。累积机制就是被用户连否三次的第 2/3/4 代 |
| 不要用"固定事件次数"作音量依据（03 §3.4 末） | 每事件一步 | **有保留地作废**。该结论的前提是"设备事件频率差异大"，但实测事件率差异远小于 `deltaY` 量级差异；按位移反而在高精度设备上攒不满 |
| 默认步进 2%，Shift 激活 1% 精细步进 | **2%/格**；Shift 不占用（另有主：等比缩放拖拽） | **采纳步进值，放弃 Shift 精细档** |
| `deltaMode === 2`（整页）忽略 | 已补 | **采纳** |
| 横向滚轮不处理 | 已补：`|deltaX| > |deltaY|` 时让行 | **采纳** |
| Ctrl+滚轮排除 | **反转**：Ctrl+滚轮成为唯一触发方式，其余滚轮一律不动 | **反向采纳**（排除的是"无修饰键也接管"） |
| 拖动滑块/进度条时滚轮不叠加 | 已补：`seeking || volDrag` 时让行 | **采纳** |
| 以 `volumechange` 为唯一状态依据 | 已补：监听 `volumechange → renderVolume` | **采纳**（外部改 `muted/volume` 时 UI 现在会跟随） |
| OSD 单实例复用、滚动停止 700~1000ms 后隐藏 | 单实例复用，1300ms | **采纳**（时长保留） |
| 静音时滚轮自动解除静音、以静音前音量为基础 | 已实现 | **采纳** |
| 音量 clamp 0~1、撞界清理累积 | 已实现 | **采纳** |
| 启动时做音量接口能力检测（`volume` 是否真生效） | 未做 | **未采纳**：桌面 Chrome/Edge 实测 `audio.volume` 生效；若将来上移动 Safari 再补 |
| `AbortController` 管理监听生命周期 | 未做 | **不适用**：单页单实例播放器，不存在重建 |

- 另补三条硬过滤（三条都实测过"音量不变"）：`deltaMode === 2` 整页单位忽略、`|deltaX| > |deltaY|` 让行（横向/触控板水平手势）、`seeking || volDrag` 时让行（拖进度条或拖音量滑块时滚轮不叠加）。
- 陷阱：合成 `WheelEvent` **不会触发浏览器默认滚动**，所以"列表内"只能验证"没抢音量"，真实滚动行为必须靠人手验证。

### B2. 悬停热区自动收面板
- 面板是**滑到指针下方**而不是指针移进面板，这种情形浏览器不保证补发 `mouseenter`；只靠 `insideDrawer` 布尔标志会在到点检查时误判"鼠标不在面板内"而收起。
- 正确做法：全局捕获 `mouseover` / `pointermove` 记录实时坐标，判定一律用 `getBoundingClientRect()` + **外扩容差**（本项目 12px，因为用户视觉上认为"还贴着边缘"），并用 `setInterval` 巡检；`mouseenter/mouseleave` 只做快速通道；延迟收起前**再复核一次几何**。
- 悬停弹出还要配：停留门槛（150ms）、滑入时长（800ms）、保持期（5s）、静默期（2s），否则快速掠过会反复开合。

### B2b. 点面板外面立即收回（不受保持期限制）
抽屉已有三套收起机制（边界悬停、保持期到期巡检、右上角按钮），都不覆盖"用户点空白处"：保持期内的点击毫无反应，按钮打开的更是永不自收。
- 挂 `document` 级 `pointerdown`，**必须用捕获阶段**（`addEventListener(..., true)`）：抽屉内部控件常带 `stopPropagation`，冒泡阶段会漏掉。
- 用 `pointerdown` 而不是 `click`：按下即响应，不等抬手，符合"点了就收"的直觉；顺带不会因为抬手落在别处而丢事件。
- 三种"不算外面"必须排除：① `d.contains(target)`（点内部选目录/点曲目）；② `target.closest('#folderAddBtn')` 这类**它自己的开关按钮**（否则本体先收、再被 toggle 重新打开，观感是"点了没反应"）；③ `.edge-left / .edge-right` 边缘热区（那是悬停唤出入口，不是离开）。
- 三套机制共存时的规则：点外部**无视**保持期，也**无视**固定态（点外面就是想关）—— `closeDrawer` 内部会顺手把 `pinned` 复位并同步按钮高亮。

### B3. 点击开合 vs 拖拽
- 可拖拽浮层内的开合点击，必须在**捕获期**记录 `pointerdown/pointerup` 位移，≤5px 才算点击，否则拖拽结束会误触发。
- 过渡动画期间用时间锁（`COVER_LOCK_MS`）+ 撞锁惩罚（连续点击计数）压连点；实测连点 4 次只切 1 次。

### B4. 触摸/滑动手感
`bu.drag` 在这类页面上会报 `actor_kDragAndReleaseToMoveSuppressed`，需改 `dispatchEvent(new PointerEvent(...))` 模拟。

## C. 动效与时序

### C1. 多元素同曲线同步位移
多个绝对定位元素靠自定义属性控制左缘时，只给 `width` 加过渡会让内容瞬间跳位。**把自定义属性注册成 `@property`（`syntax:'<length>'`）** 并纳入同一 `transition`，才能与 `width`/`transform` 逐帧同步。
- 本项目：`.player` 的 `--cx`（内容左缘）与 `--cover-x`（封面左缘）都是 `@property`，四条过渡同曲线同长（1.2s `cubic-bezier(.19,1,.22,1)`）。

### C2. 半透明容器下内容滑过 → 用几何裁剪，不要用不透明蒙版
- 用户明确拒绝"用不透明等效底色盖住"的方案。
- 采用 `clip-path: inset(0 0 0 calc(330px - var(--cover-x)))`：左裁量 = `330 − 封面left`，逐帧恒等，唱片区零泄漏，观感是"从唱片右缘揭开"而不是"从唱片底下钻出"。
- 关键帧动画里也要带 clip，否则 `cover-slide-in` 会溢出。

### C3. 用户说"变快了"不一定是时长变了
先确认参数是否真改过；再用位移采样算各阶段完成比例。`cubic-bezier(.19,1,.22,1)` 起步极快（0.3s 走 47%、0.6s 走 93%），时长没变但体感"急"。要"稳"就换近线性 `cubic-bezier(.4,.15,.6,.85)`。

### C4. 时长预算按"全程"算
用户说"整个弹出控制在 950ms"时，要拆成：150ms 检测预留 + 800ms 动画 = 950ms，而不是把动画本身设成 950ms。

### C5. 已在展开态换内容不会重播位移过渡
用一次性动画类补播入场（本项目 `.replay` → `cover-slide-in` + `cover-fade-in`，2s 后摘除），不要清空重建，否则会先回缩再弹出。

### C6. 先收拢再切内容
面板已展开时点切换，应先按过渡收回、确认复位后再换内容；用 `switchSettleUntil` 时间门 + `settled` 校验防抢占，窗口内点击直接吞。本项目实测：242ms 开始收 → 1442ms 视觉复位 → 1804ms 切歌 + 新封面滑出。

### C7. 歌词动效
两行滚动 + 逐字 `--k` + 呼吸（±2px / 5.2s）三者共存时，换句用行位移、逐字用 `background-clip: text` 的进度值、呼吸用极低频 transform；避免每帧重排，行高变化用固定高度容器裁。

### C8. 切歌要做"唱针仪式"，不是换个 src
只切 `audio.src` 时，`.playing` 类几乎同帧翻转（`pause`→`load`→`play` 只有几十毫秒），用户看到的是"唱片一直在转、歌突然换了"。
所以切歌必须是一张**显式的节拍表**（全部相对点击时刻）：

| 时刻 | 动作 | 常量 |
|---|---|---|
| 0 | 点击「下一首/上一首」 | — |
| 0 ~ 300ms | **留白**：什么都不动 | `CUE_PRE_MS = 300` |
| 300ms | 抬针开始（`transform` 过渡 .48s）+ 展开态同时开始收拢 | — |
| 500ms | 针已离盘 → 停转 + 停声 | `CUE_LIFT_SETTLE_MS = 200` |
| 300 + 1500ms | 展开态换片（新歌起播）；收起态是 300 + 520ms | `CUE_COLLAPSE_MS` / `CUE_SWITCH_MS` |
| 换片 + 200ms | 盘已起转 → 针开始落 | `CUE_DROP_DELAY_MS = 200` |
| 换片 + 680ms | 针落回盘面 | — |

- **留白是最关键的一段**：没有它，抬针和点击同帧启动，用户感觉"一按针就弹起来了"，三个动作糊成一团。300ms 是他能明确感知"我按了 → 然后唱片开始反应"的最小间隔。
- 抬针曲线用 `.48s cubic-bezier(.3,.05,.55,.95)`（起手缓、中段匀速）。原来的 `.34,.9,.4,1` 起步太陡，视觉上像弹簧弹出，与"留白"的效果互相抵消。
- CSS 里 `.player.cue-up .disc .disc-arm{transform:rotate(-16deg)}` 必须写在 `.player.playing …` **之后**（同特异性，靠顺序取胜）。
- 停声跟着抬针：`CUE_LIFT_SETTLE_MS` 后再 `pause()`，避免"盘停了声音还在"。
- 实测（展开态，每 90ms 采样 `sin(rotate)` 与 class）：0–277ms 完全静止 → 362ms 针开始动 → 546ms 停转+停声（此时针已抬 8°）→ 905ms 抬到 -16° → 1802ms 换片起播 → 2079ms 开始落 → 2530ms 落回 0°。

### C9. 唱片转速要有加减速，不能用固定时长 CSS 动画
`animation: discSpin 14s linear infinite` + `animation-play-state` 只有"转/不转"两档，起播和停转都没有过渡，所以用户看到的是一个开关。
改法：**JS 逐帧写 `rotate`**，转速用一阶惯性追目标。
- 目标 = 基准 `0.20 rps`（5s/圈）× 节拍增益；`!playing` 或 `cue-still` 时目标为 0。
- 加速 `τ=0.42s`（约 1s 到速）、减速 `τ=1.15s`（约 2.5s 滑停）。**加速和减速的时间常数必须分开**，共用一个会让起播拖沓或停车急刹。
- 节拍增益取 `visualizer.getBeat()`（该模块内部的前 12 bins ≈ 0~500Hz 低频能量），先按 `dt*5` 慢平滑再乘，直接乘原始值会让转速抖。
- 停稳（`rps < 0.002` 且目标 0）时主动停掉 rAF，别在后台空转；`setDiscPlaying` / `armCueDown` 里 `discWake()` 唤醒。
- 实测：播放稳态 6~7 deg/100ms（≈5s/圈，节拍强时到 9.7 → 3.7s/圈）；暂停后 8.2 → 5.3 → 1.9 → 0.3 deg/100ms，约 2.5s 停稳。
- 采样坑：100ms 采样 `style.transform` 会看到"大值/小值交替"的拍频假象（0.4 与 9.1 交替），是掉帧 + 读取时刻造成的，**不代表转速真的在跳**，看趋势不看单点。

### C10. 给白色 SVG 图标上色：`sepia` 直接套纯白是无效的
盘心音符（`.disc-music`，白色描边 SVG）要做成"跟随歌名标题变色 + 辉光呼吸"。
- **染色不能这么写**：`sepia(1) saturate(5) hue-rotate(H)`。sepia 对纯白输出仍接近白（~#FFFFEF），饱和度极低，后面 saturate 放不出颜色，实测像素前后都是 `(255,252,255)` —— 看起来 filter 完全没生效。**用 `invert(1)` 反相也不对**：原图是白音符，反相后变成黑点。
- **能用的链路**：`invert(0.5)`（白 → 中灰，这是关键一步）→ `sepia(1)`（灰 → 暖棕）→ `saturate(6.2)` → `hue-rotate(H)` → `brightness(1.02~1.36)` → `drop-shadow(0 0 Npx hsla(H,...))`。
- `brightness` 上限必须压在 1.4 左右：实测 1.6 以上会把颜色冲回接近白，音符又"变白"。
- `hue-rotate` 必须排在 `drop-shadow` **之前**，否则已生成的阴影颜色会被再旋一次，辉光和本体就不一个色。
- 与标题"同色"的做法：标题动效开着时直接 `noteHue = fxHue`（严格同相），关着时用同一套规则自演进；实测同一时刻标题 `rgb(246,173,90)`(hue≈33) 对应音符 `hue-rotate(32deg)`、标题 `rgb(87,215,246)`(hue≈194) 对应 `hue-rotate(192deg)`。
- 辉光呼吸灯 = 3.4s 正弦波叠加在 `brightness` 与 `drop-shadow` 半径上（亮度 1.34↔1.56、光晕 6↔16px 周期起伏），节拍能量再往上叠一层脉冲。
- **护栏**：`audio.paused` 不够用 —— 欢迎页/没媒体时 UI 已切到"暂停"图标，`paused` 可能是 `false` 但 `currentSrc` 为空，音符会自己在欢迎页上呼吸。判据用 `paused || !currentSrc`。

### C11. 唱针"活着"的微颤：幅度按针尖像素算，且必须让位给状态类
目标不是"抖"，是"不像一张静止的图片"——针尖有 2~3px 的不规律位移，观感是呼吸级别，不是抖动级别。
- **幅度要按针尖位移反算角度**：支点到针尖约 154px，`1px ≈ 0.37°`。想要峰峰 3px，就把关键帧总和控制在 ±0.6° 附近；凭"看起来差不多"给的 ±0.85° 实测是 4.2px，偏大一倍（用 `getComputedStyle().transform` 的 matrix 反解角度、采样 38 次取 min/max，换算成 px 才知道）。
- **用 CSS `animation` 而不是 JS 逐帧**：唱针平时由 `transform: rotate(0/-16deg)` + `.48s` 过渡控制，JS 写 inline transform 会打断过渡。但 `animation` 优先级高于普通声明，**会盖掉抬针**——所以必须补一条 `.player.cue-up .disc .disc-arm { animation: none; }`，并且写在 `.playing` 的 animation 规则**之后**（同特异性看书写顺序）。
- **加 `animation-delay`**：`0.5s`，等落针过渡（0.48s）走完再开始抖。否则起播瞬间针会"瞬移归位 + 立刻抖"，落针动效被吃掉。
- **不规律才像活的**：关键帧给 6 段不对称值（`0 / -0.6 / +0.25 / -0.2 / +0.53 / -0.35 / 0`），单周期 1.4s。做成对称正弦会像机械摆动。
- 实测四种状态：播放中摆幅 1.13°（3.0px）；暂停恒定 -16°（采样 38 次 min=max）；切歌抬针期恒定 -16°（动画确实被 cue-up 关掉）；落针后恢复 3px 摆幅。

### C12. 顶部歌词轮播：随机时刻要"只摇一次"，双语要按时间就近挂
把 header 文字信息在起播后随机时刻换成两行滚动歌词，四个坑都在浏览器里量出来的。
- **随机时刻只能摇一次，且要能被晚到的歌词复用**：`play` 事件常常比 `/api/lyrics` 早到（在线刮削要几秒）。若在 `play` 里"看到没词就 return"，之后就再没有入口，歌词永远不出现。做法是 `play` 时先摇一个目标时刻 `hdTargetAt = now + Math.random()*2700`，歌词后到的 `applyLyrics` 只补排定时、复用同一个目标——保证"歌词晚到也不会突破上限"。
- **别把 `3000` 当上限写死**：实测事件派发有 ~240ms 系统性抖动，写 3000 会量出 3237/3449 的越界样本。把随机区间收到 2700，实测 136 / 629 / 1773 / 2015 / 2078 / 2138 / 2720 全部落在 3s 内。
- **补排必须幂等，否则会闪**：同一首曲内 `applyLyrics` 会被反复调用（缓存命中、刮削回填）。每次补排都 `classList.remove('lyrics-mode')` 再 `setTimeout(add)`，就会出现"进入 → 撤掉 → 再进入"。给 `hdArmRandom(force)`：已在歌词态或已有计时器就直接 return，只有切歌/新曲用 `force=true` 打断。同理，无歌词分支在**播放中不要调 `hdRestore()`**（可能还在等刮削）。
- **曲终 3 秒恢复会被下一首挤掉**：`ended` 后轮播立刻起下一首，实测恢复与切走只隔 14ms。修法是 `ended` 时记 `hdHoldUntil = now + 3000`，新曲 `hdTargetAt = max(now + random, hdHoldUntil)`——新曲的随机目标不得早于保底窗口结束。实测曲末 `OFF@33582 → ON@36585`，正好 3003ms。
- **双语数据**：网易云接口本来就带 `tlyric`，只取 `lrc` 就会丢掉译文。服务端 `parseLrc` 后按时间**就近**（容差 0.6s、游标单向推进、`used` 防重复）把译文挂到主行；前端再把"同一时间戳紧邻两行"的双语 lrc 写法合并成 `{time, text, trans}`。
- **滚动本体**：`.hd-lyric-track` 用 `translate3d(100vw → -102%)` 的 `animation`，时长按文字宽度 ÷ `HD_SCROLL_SPEED(190)` 算并夹在 4.5~7.5s；换句必须 `animationName='none'` + `void offsetWidth` + 复原强制重播，否则新句不会从右缘重新进场。两端渐隐用 `mask-image` 7%/93%，暂停时 `animation-play-state: paused`。

## D. 浏览器实测与调试

### D1. 改了代码没生效 → 先查缓存
`index.html` 引用的 `app.js`/`style.css` 没有版本串时，浏览器吃缓存会让你以为代码没生效，白查一轮。**每次改完升 `?v=` 字母**，并用 `window.__errs` + `addEventListener('error')` 兜底。

### D2. 验证交互要用真实命中点击
`js().click()` 会绕过命中检测，掩盖"元素被别的层遮住，真实用户点不到"的问题。交互验证一律用真实点击（`bu.click`），只有纯逻辑才用 JS 调用。

### D3. 几何/动效必须量，不要看
用 `getComputedStyle` + `getBoundingClientRect` 定时采样（100~150ms）记录过程值；截图只做观感佐证。典型断言：`clip 左裁量 == 330 − 封面left` 逐帧恒等；内容区左缘 − 封面左缘恒为 320px。

### D4. 浏览器工具坑（browser-use）
- `bu.js()` 长表达式/多语句**静默无输出**：先 `bu.resync()`，再发极短单查询。
- `bu.screenshot` 必须绝对路径（相对名会落到 `public\`）。
- `bu.scroll` 对非可滚动目标报 `actor_kScrollTargetNotUserScrollable`；`bu.cdp` 常报 `Session with given id not found`。
- `bu.navigate('reload')` 偶发落 `about:blank`，需再 navigate 绝对 URL。
- 桌面级 `cu`（Windows）在本机可能因授权重试超限不可用，注入真实硬件滚轮这条路走不通——只能做事件级实测，硬件 `deltaMode`/事件频率永远存在证据缺口，要在交付时如实说明。

### D5. 截图/读图
超过 5MiB 的 PNG 直接 Read 会超限（base64 上限），先用 PIL 裁切或缩放再读。

## E. 后端与数据

### E1. 播放"疯狂跳过"的两大来源
- 数据层：一批文件流播失败（路径失效、格式不支持、网络盘断连）→ 每首 error 继续跳。
- 逻辑层：`play().catch` 与 `audio 'error'` **双触发竞态**——失败文件的滞留 error 事件晚于 `advance()` 到达，此时 idx 已推进，error handler 把下一首正常文件也跳掉，连锁放大。
- 修法：播放引擎用**批次代次 token** 校验所有异步回调，`reset()` 作废在途回调，`pendingFail` 定时接管防双跳，连续失败 `FUSE=10` 熔断。

### E2. 恢复播放前必须校验路径
`POST /api/check-paths` 批量校验（上限 5000），恢复前预过滤失效文件并提示，否则"恢复即崩"。

### E3. 扫描要有硬上限
`MAX_SCAN_FILES=100000` + 扫描超时 + `truncated` 标记；前端对盘符根目录（`C:\`）强警告二次确认。

### E4. 网络请求要做序号校验
快速切歌时旧封面/歌词请求可能晚于新曲返回，导致"张冠李戴"。`loadCover` 用 `activePath`、歌词用 `lyricsPath` 校验，不匹配就丢弃。

### E5. 持久化要版本化
`SESSION_VERSION=1` + `migrateSession`（v0→v1 规范化字段），`loadSession` 迁移后回写；坏存档 try/catch 降级为新会话。

### E6. 打开路径：目录与文件是两条命令
`explorer.exe "<dir>"`（打开目录）与 `explorer.exe /select,"<file>"`（定位文件）不同；用一个 `/api/open-path` 按 `stat` 结果分派，不存在路径返回 `{ok:false, error:"ENOENT"}`。

### E7. 服务端只读
后端没有任何 `unlink`/删除接口，前端也没有删除文件的入口；「清空残留」只清浏览器 IndexedDB 会话缓存。这是对用户的明确承诺，不要破坏。
